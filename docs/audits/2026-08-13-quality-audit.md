## 総評

公開を止めるP0は確認されなかった。既存実装は、Firebase匿名認証、部屋・席・送信者の照合、受信パケット検査、ユーザー文字列を`textContent`で描画するXSS対策、Stage Studioのモーション低減、1,342件の自動テストなど、ゲーム規模に対して防御が厚い。

監査中にSol級サブエージェント6系統も起動したが、最終報告前に利用上限へ達したため、未完了の内容は監査証拠として採用していない。以下は主担当が実ファイルで再確認できた項目だけである。

### 確認できた強み

- ロビーのユーザー文字列は`document.createElement`と`textContent`で組み立て、文字列連結の`innerHTML`を避けている。
- Firebaseルールは既定拒否で、部屋コード形式、期限、席UID、ホスト専用操作、メッセージ種別と主要数値範囲を検査している。
- 受信側にも送信席、手番、アクションID、状態整合性の検査があり、DBルールだけへ依存していない。
- Stage Studioはランドマーク、ラベル、`aria-live`、Canvas名、モーション低減を備える。
- 音声の大半は必須キャッシュへ入れず、必要なステージ・演出時に読む構成である。リポジトリ総容量と初期転送量は同一ではない。

- **P0**: 情報漏えい、不正操作、広範なデータ破壊、公開版の主要機能停止へ直結し、直ちに封じ込めが必要。
- **P1**: 一般的な操作で利用者影響が発生し得る、または運用事故・重大な性能劣化の可能性が高く、次の開発版群で優先対応。
- **P2**: 条件付きの不具合、アクセシビリティ不足、保守コスト、不要転送など、計画的に改善すべきもの。
- **P3**: 将来の拡張性、開発体験、軽微な統一感など、中長期で検討するもの。

重大度はコード上の危険な書き方だけで決めず、到達可能性、既存の防御、実際の利用者影響、修正時の回帰リスクを含めて判断する。

## 推奨する改善ロードマップ

各項目を独立したブランチ・版・PRとして分離し、実装前に旧実装で新テストが失敗することを確認する。視覚変更はローカルHTTP＋実ブラウザ、オンライン・描画関連は全テストとloopback中継数を品質ゲートとする。

推奨順序は次のとおり。

1. **v182 / SEC-01**: ランキング名の数式無害化。狭く、テスト可能で、管理側の安全性へ直接効く。
2. **CI限定PR / CI-01**: PRの二重実行を解消し、以降の改善コストを下げる。
3. **v183候補 / PERF-01**: フォントWOFF2サブセット化。見た目の実測確認を伴うため独立させる。
4. **Firebase専用版 / REL-01**: ルールとエミュレータ試験を先に完成させ、メロニキへConsole反映を依頼してから公開する。
5. **UX・ARCHの小分け改善**: Canvas説明、演出低減、純粋関数の契約テスト、モジュール抽出の順に進める。

各実装PRの共通完了条件は次のとおり。

- 変更目的が1つで、無関係な整理を含まない。
- 新しい回帰テストを追加する場合、修正前コードで狙った1件が失敗し、件数表示が残ることを先に確認する。
- 最終テストの成功件数を`CURRENT_WORK_STATE.md`へ記録する。
- `loopbacktest`の中継数が **38 / 64 / 83 / 61 / 48** のままであることを確認する。
- 視覚変更はローカルHTTPと実ブラウザで確認する。
- アプリを配信する版では`BUILD_ID`と`CACHE_VERSION`を同じ番号へ更新する。

## 変更してはいけないこと

- 監査だけのPRへアプリ実装や無関係な整理を混ぜない。
- 内部キャラクターキー、対戦プロトコル、ランキング保存値を表示名・画像名へ置換しない。
- 描画だけの変更でloopback中継数を変えない。
- `BUILD_ID`と`CACHE_VERSION`を別番号にしない。
- `database.rules.json`を変更した版は、Firebase Console反映を依頼する前に公開しない。
- ランキングGASのリポジトリ上の修正と、本番Apps Scriptへの再デプロイ済み状態を混同しない。
