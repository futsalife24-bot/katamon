## 2. 直近のセッションでやったこと(v58 → v77)

### 2-1. Stage 4:放置された部屋が塞がる問題(**達成**)

固定コードの簡単対戦(`KATAMN22`)が、ホストのゴーストに握られると**最大2時間詰む**問題を解消した。

- **v59** ロビー専用の心拍を**別系統**で新設(15秒ごとに `ping`、45秒途切れたら席ボードに「応答なし」)。
  **対戦中の判定(10s/35s・切断あり)と統合してはいけない。** ロビー側は表示だけで切断しない
- **v61** 部屋の期限を **2時間→10分**にし、ホストが60秒ごとに前へ延ばす。ホストが消えれば10分で
  期限切れになり、**既存の「期限切れは誰でも上書き」ルールがそのまま発火する**。
  乗っ取りの仕組みを新設しないのが設計の要点。**本番で8/8検証済み**
- **v62** 通信エラー・版不一致・相手の退出でタイトルへ抜ける経路が部屋を置き去りにしていた。
  `round.status` が `playing` のまま残ると席の確保ができず**誰も入れない**。実機で実際に詰まった

**ルール変更は `expiresAt` に `.write` を1つ足しただけ。2026-07-28にConsole反映済み。**
上限(2時間)は据え置いてある。**縮めると旧版を掴んだ端末が部屋を作れなくなる。**

### 2-2. ダメージ ── 入れて、壊して、戻した(**この失敗は繰り返さないこと**)

**v63で「帯ごとの固定値」にしたのは失敗で、v66で元の傾斜へ戻した。**

狙いは「オンラインで同期のたびにHPの小修正が見える」の解消だった。しかし
**直撃の境界は20px、キャラ中心から足元までは16px**。足元撃ちは距離16〜25pxに散らばって
ちょうど境界をまたぐため、固定値だとそこが**10ダメージの崖**になる。立ち位置と地面の傾きで
どちら側に落ちるかがほぼ決まるので、**片方だけ毎回45・もう片方は毎回35**という不公平が出た。

> **教訓:連続量を離散化する時は、境界が「よく起きる値」の上に乗らないか確認する。**

検査も「帯の中で一定」ではなく「**隣り合う距離で崖が無い(差3以下)**」に書き換えてある。

**v67が元の要望への正解。** 受け側も弾道を自前で再現して見積もりをポップさせ、直後に届く
権威ある値でHPだけ上書きされるので**数字が後から動いていた**。相手の弾による被弾では
ポップを出さず、権威ある値が届いた時点で差分を出す。**計算式には触らないのでバランスは動かない。**

**固定ステップ案は測って捨てた。** 60fpsと120fpsの着弾差は標準的な山なりで0.3px、
低く速い弾で約9px。9pxは傾斜で6ダメージ相当にしかならず、報告の10には届かない。
**弾の飛び方が変わる副作用のわりに効果が中途半端。**

### 2-3. コミット・公開の順序バグ(**この経路は無検査だった**)

**v69。** 実機で「キャラクター確認が一致しません」が出て両者が動けなくなった。

`acceptPeerCommit` が「まだ公開前なら新しいもので上書きしてよい」だけで判断していたため、
**古いコミットが後から届くと最新を上書きし**、続く公開が一致しなくなる。
**相手が準備完了を押し直した時にだけ**コミットが2つ飛ぶので、1回で決めている限り出なかった。
送信時刻(`sentAt`)で古いものを落とすようにした。

**`loopbacktest.js` はv2のプロトコルで動き、キャラのコミット・公開はv3ロビーの機能なので
一度も通っていなかった。** `tests/lobbysimtest.js` を新設して埋めた。ゲームは動かさず本体の
判定関数だけを呼び、**配送順を変えて**結果を見る。**「通ってはいけない」検査(公開より先の
コミット、公開後の差し替え)が入っているので、不正防止を緩めると落ちる。**

**v68** で行き止まりも塞いだ。検証で止まると `phase` は `revealing` のままで、退出は
`lobby` 以外を一律で断っていたため**退出も再戦もできなかった**。

### 2-4. 見た目まわり(v60・v62〜v65・v70〜v77)

- 対戦中の切断でも「オンライン対戦を**開始**できません」と出ていた → `matchStarted` で出し分け
- 名前カードを**キャラが立っている側**へ(ゲストは「名前が左・自キャラは右」を見ていた)。
  判定は位置ではなく**席**で行う。陣営色は置いた側ではなく**持ち主**で引く
- 出撃ギアの逆回転(v55の符号ミス)、歯の大きさ、矢印の削除、性能メーターの群の間隔
- 闘技場でCPUが自分から奈落へ歩き込んで自滅していた → `cpuStepIsSafe()`。
  **プレイヤーには適用しない**(自分の意思で落ちるのは操作の自由)
- 闘技場の外壁を画面上端まで伸ばし(v70)、弾の判定も付けた(v71)。
  **`solidGrid` は広げていない**(行を増やすと全走査が重くなる)。`isSolidAt` の `y<0` の
  早期returnを範囲判定に差し替えただけなので、**通常の飛行中は比較が1つも増えない**。
  上端より上は削れないので「壊れない岩盤」という割り切り
- 中断データの告知を**マンガ風の吹き出し**にした(v72〜v75)。
  **ここだけ世界観から浮いているのは意図した結果。** 最初は黒鉄+真鍮で作って背景に完全に
  溶けたため。「他と揃っていない」という理由で直さないこと
- 中断データを消す前の**3択確認**(v76〜v77)。`selectCharacterAndStart()` は入口で
  `clearSuspendedMatch()` を呼ぶので、素通しすると押した瞬間に消えて戻せない

## 5. 効いたやり方

- **推測で直さず、本番と実機を見る。** 簡単対戦が「利用中」のままだった件は、本番へ実際に
  投げて「3席とも401・新規作成も401」を確認したから、席の空きではなく `round.status` が
  固まっていると特定できた
- **再現してから直す。** コミットの順序バグは、配送順を変えるシミュレーションで再現させて
  から直した。**再現がそのまま回帰テストになった**
- **前提そのものを検査に入れる。** 「CPUが奈落へ踏み込まない」だけだと、地形が変わって中央が
  奈落でなくなった時に素通りで通る。「中央が本当に死線へ届く奈落であること」を先に確かめている
- **見た目は数値で押さえる。** Canvasの描画は自動で見られないので、
  「画面内に収まる/他の要素に被らない/はみ出さない」を座標の関係として検査に書く。
  この方式で**実際に3件**捕まえた(吹き出しの左はみ出し、本文がボタンに隠れる、ボタンの重なり)
- **段階を切る。** 表示だけの変更を先に出し、ルール変更を後に回す。
  ルールを触った時に不具合が出れば原因が一意に決まる

## 6. 環境の罠(踏むと時間を溶かす)

- **`core.autocrlf=true` で作業ツリーがCRLFになる。** スクリプトで文字列置換する時、
  改行を含むマーカーは一致しない。**アンカーは1行に収めること**
- **スクリーンショットが撮れない**(Claude側の制約。Codexで撮れるなら状況は改善する)。
  DOMなら `getComputedStyle` を読めるが、**Canvasの描画は検証できない**。
  見た目の変更は必ず「実機で目視してほしい」と伝えること
- **別のセッションが同じリポジトリを触ることがある。** 実際に1コミット入っていた(`92983a9`)。
  **着手前に必ず `git log` と `git status` を見る**
- **`loopbacktest.js` は子プロセスを2つ立てる。** harness は `globalThis` にゲームを展開する
  ので、1プロセスに2インスタンスは置けない
- **`peer.js` は `Math.random` を固定シードに差し替えて試合を決定化している。**
  中継メッセージ数まで毎回一致するのが決定性の目印。ここがブレたら乱数以外の非決定性が
  混ざったサイン。別の展開を見たい時は `KATAMON_TEST_SEED`
- **プレビューサーバのルートはカタモンフォルダ。** `/カタモン/index.html` は空ページになる
