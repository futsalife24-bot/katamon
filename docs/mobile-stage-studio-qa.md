# Stage Studio モバイルQA計画・記録

更新日: 2026-08-06

## 1. 判定ルール

PlaywrightのWebKit・Chromiumテストは「iPhone相当」「Android相当」のブラウザエンジン、縦画面、タッチ入力を自動確認する。これは実機Safari、実機Chrome、ホーム画面Webアプリ、インストール済みPWAの確認とは別物である。

最終報告では次を混同しない。

- 自動テスト成功
- デスクトップ実ブラウザでの手動確認
- iPhone実機Safari
- iPhone実機ホーム画面Webアプリ
- Android実機Chrome
- Android実機インストール済みPWA

未実施の項目を「確認済み」と表現しない。

## 2. 自動テスト環境

| Project | Engine | Viewport | Touch | 用途 |
|---|---|---:|---|---|
| `iphone-webkit-portrait-touch` | WebKit | 390 × 844 | 有効 | iPhone縦画面相当 |
| `android-chromium-portrait-touch` | Chromium | 412 × 915 | 有効 | Android縦画面相当 |

実行手順：

```bash
npm install
npm run e2e:install
npm run e2e
```

既にローカルサーバーを起動している場合：

```bash
npm run serve
```

別ターミナルで`STAGE_STUDIO_BASE_URL`を指定して実行できる。

## 3. 自動E2Eの対象フロー

`tests/e2e/stage-studio.spec.js`で次を確認する。

1. Stage Studioを縦画面で開く。
2. 新規作成を選ぶ。
3. プリセットとシードを設定する。
4. 決定的地形を生成する。
5. Canvasをタッチ相当のポインター操作で編集する。
6. UndoとRedoを実行する。
7. 地形画面で背景・地形の見た目とキャラクター寸法ガイドを確認する。
8. 出撃地点画面を開き、自動配置または配置確認を行う。
9. テスト画面で全体風を設定し、共有物理によるテスト砲撃を実行する。
10. 自動検証でエラー0件を確認する。
11. JSONとZIPのダウンロードを確認する。
12. ページ再読込後に下書きが残ることを確認する。
13. ゲーム側でJSONをインポートする。
14. カスタムステージ一覧から選び、バトルを開始する。
15. ゲームを再読込し、インポート済みステージが一覧へ残ることを確認する。
16. そのステージを選び、Bridge状態が`battle`になったことを確認する。
17. 一時配信サーバーを停止し、Service Workerのキャッシュだけでアプリシェルを再読込する。
18. 初回表示で誤った更新通知が出ず、下部ナビが縦画面内に収まり、ページ全体に縦横の不要なスクロールが出ないことを確認する。

UIの安定した契約には`data-testid`を使う。表示文言だけに依存しない。

## 9. 共通の編集QA

### ホーム・下書き

- [ ] 新規作成、再開、インポート、最近作成、保存済み、使用量、版、利用方法が表示される。
- [ ] `利用方法`が折りたたまれず常時表示され、その後に`端末の状態`が表示される。
- [ ] 下部ナビゲーションが`ホーム / 新規 / 生成 / 地形 / 出撃 / テスト / 検証 / 共有`の8工程である。
- [ ] 旧下書きの`風`工程は`テスト`、`見た目`工程は`地形`へ移行される。
- [ ] 操作後に保存日時が更新される。
- [ ] 複製が別`stageId`として保存される。
- [ ] 名前変更で内容ハッシュが再計算される。
- [ ] 削除確認をキャンセルでき、対象外の下書きは変化しない。
- [ ] 容量不足を日本語で案内し、JSONバックアップへ誘導する。
- [ ] 壊れた下書きを安全に隔離または拒否する。

### 生成・地形

- [ ] 同じseed、版、preset、parameterで同じ地形になる。
- [ ] seedを変えると生成内容が変わる。
- [ ] 描く、削る、Undo、Redoが動く。
- [ ] ブラシサイズ、硬さ、グリッド、衝突表示が反映される。
- [ ] ツールロック中に誤編集されない。
- [ ] Undo履歴上限到達後もアプリが操作可能である。
- [ ] 重い処理中に進捗と中止操作を利用できる。
- [ ] 低性能モードでも主要操作を完了できる。
- [ ] 草原、砂漠、雪原、火山で対象ゲームと同系統の背景と地形質感が描画される。
- [ ] 背景・地形色・明るさ・装飾表示を`地形`画面だけで設定できる。
- [ ] キャラクター寸法ガイドをドラッグでき、ステージの正規データへ含まれない。
- [ ] キャラクター当たり判定が地形へ重なる、または画面外へ出ると赤色の警告が表示される。
- [ ] `壊れない鋼鉄（準備中）`は無効表示で選択できず、下書きと出力データへ含まれない。

### 出撃地点・テスト設定

- [ ] 2人と4人を切り替えられる。
- [ ] 地面吸着、重なり、地形内部、画面外を検出する。
- [ ] 崖付近と左右不公平を警告する。
- [ ] 出撃地点のキャラクター表示が対象ゲームと同じ寸法である。
- [ ] 風向きと強さがテスト砲撃へ反映される。
- [ ] 風の設定を`テスト`画面だけで完了できる。
- [ ] 未対応ギミックを出力へ含められない。
- [ ] 許可された4背景だけを保存できる。
- [ ] 明るさを変えてもキャラクター仮表示を確認できる。

### テスト・検証・出力

- [ ] 移動、落下、角度、威力、弾道、着弾、爆発、地形破壊を確認できる。
- [ ] リセットで編集開始時の地形へ戻る。
- [ ] エラーがあるステージは共有できない。
- [ ] 公平性警告だけなら保存できる。
- [ ] 共有前に名前、作成者、形式、容量、互換性、警告件数、ハッシュが見える。
- [ ] JSONとZIPを出力し、同じステージへ往復できる。
- [ ] 改変したJSONはハッシュ不一致で拒否される。
- [ ] 破損ZIP、過大ZIP、危険パス、外部URL、非有限数を拒否する。
