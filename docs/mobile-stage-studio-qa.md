# Stage Studio モバイルQA計画・記録

更新日: 2026-08-08

## 1. 判定ルール

PlaywrightのWebKit・Chromiumテストは「iPhone相当」「Android相当」のブラウザエンジン、縦画面、タッチ入力を自動確認する。これは実機Safari、実機Chrome、ホーム画面Webアプリ、インストール済みPWAの確認とは別物である。

最終報告では次を混同しない。

- 自動テスト成功
- デスクトップ実ブラウザでの手動確認
- iPhone実機Safari
- iPhone実機ホーム画面Webアプリ
- Android実機Chrome
- Android実機インストール済みPWA

未実施の項目を「確認済み」と表現しない。

## 2. 自動テスト環境

| Project | Engine | Viewport | Touch | 用途 |
|---|---|---:|---|---|
| `iphone-webkit-portrait-touch` | WebKit | 390 × 844 | 有効 | iPhone縦画面相当 |
| `android-chromium-portrait-touch` | Chromium | 412 × 915 | 有効 | Android縦画面相当 |

実行手順：

```bash
npm install
npm run e2e:install
npm run e2e
```

既にローカルサーバーを起動している場合：

```bash
npm run serve
```

別ターミナルで`STAGE_STUDIO_BASE_URL`を指定して実行できる。

## 3. 自動E2Eの対象フロー

`tests/e2e/stage-studio.spec.js`で次を確認する。

1. Stage Studioを縦画面で開く。
2. 新規作成を選ぶ。
3. プリセットとシードを設定する。
4. 決定的地形を生成する。
5. Canvasをタッチ相当のポインター操作で編集する。
6. UndoとRedoを実行する。
7. 地形画面で背景・地形の見た目とキャラクター寸法ガイドを確認する。
8. 出撃地点画面を開き、自動配置または配置確認を行う。
9. テスト画面で全体風を設定し、共有物理によるテスト砲撃を実行する。
10. 自動検証でエラー0件を確認する。
11. JSONとZIPのダウンロードを確認する。
12. ページ再読込後に下書きが残ることを確認する。
13. ゲーム側でJSONをインポートする。
14. カスタムステージ一覧から選び、バトルを開始する。
15. ゲームを再読込し、インポート済みステージが一覧へ残ることを確認する。
16. そのステージを選び、Bridge状態が`battle`になったことを確認する。
17. 一時配信サーバーを停止し、Service Workerのキャッシュだけでアプリシェルを再読込する。
18. 初回表示で誤った更新通知が出ず、下部ナビが縦画面内に収まり、ページ全体に縦横の不要なスクロールが出ないことを確認する。
19. 対象ゲームの起動前とタイトルで端末の戻る操作を行い、終了確認が最前面に出ることを確認する。
20. `このまま遊ぶ`では画面を維持し、`アプリを閉じる`を明示した時だけ前のページへ戻ることを確認する。

UIの安定した契約には`data-testid`を使う。表示文言だけに依存しない。

## 4. プライベートオンライン対戦の確認

自動テストでは、ホストが選んだ正規ステージJSONを既存の開始スナップショットへ含め、参加者側で次を確認する。

- `stageId`、`schemaVersion`、`contentHash`、`gameCompatibility`の一致
- 256KBの通信上限
- JSON Schema、許可素材、ギミック、出撃地点、地形列、ハッシュの再検証
- Firebase Realtime Databaseで配列の空要素や`null`が正規化された後も同じハッシュになること
- 改ざん、識別情報の差し替え、ステージ本体欠落を開始前に拒否すること
- 全着席プレイヤーの開始確認が返るまでホスト操作をロックすること
- 観戦用スナップショットと再戦でも同じステージを再検証すること
- 公式地形のスナップショットへカスタムデータを混入できないこと

実際のFirebaseを介したiPhone・Android実機間の通信は未確認である。公開後は、同じビルドを表示している2台で「部屋作成→カスタム選択→参加→開始→再戦→観戦」を確認する。
