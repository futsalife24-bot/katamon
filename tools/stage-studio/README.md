# Stage Studio

Stage Studioは、対象ゲーム用のカスタムステージをスマートフォンで作成する静的Webアプリです。アカウント、サーバー、AI APIは使いません。地形生成・編集・検証・端末保存・JSON/ZIP出力までブラウザ内で完結します。

現在のMVPバージョンは`1.6.1-cache-refresh`です。

公開版: https://futsalife24-bot.github.io/katamon/tools/stage-studio/

## フォント

ゲーム本体と共通の2フォントを端末内で利用します。タイトル、工程名、ヒーロー見出しなど短く強く見せる文字はReggae One、ボタン、入力、説明、ステージ名など通常UIはRocknRoll Oneです。どちらも`assets/fonts/`から読み込むため、通常利用時に外部フォントサービスへ通信しません。

## 起動

Service WorkerとWeb Workerを利用するため、`file://`ではなくHTTPサーバー経由で開いてください。リポジトリ直下で次のいずれかを実行します。

```powershell
py -m http.server 4173
```

または:

```powershell
python -m http.server 4173
```

その後、`http://localhost:4173/tools/stage-studio/`を開きます。ビルド工程や環境変数はありません。

## MVPの流れ

画面下の工程は`ホーム / 新規 / 生成 / 地形 / 出撃 / テスト / 検証 / 共有`の8つです。背景などの見た目は`地形`へ、風は`テスト`へ統合しています。ホームの`利用方法`は折りたたまず常時表示し、その後に`端末の状態`を表示します。

1. 「新しいステージを作る」から白紙またはプリセットを選ぶ
2. シード、密度、谷、山、空洞率、人数、難易度などを指定して生成する
3. マップ直下の`選択中`ボタンから、描く・削る・キャラ・塗る・線・四角・円・文字・ロックを切り替える。細かな設定はマップ外の`設定`からフロートパレットを開き、ブラシ、整形、表示、見た目、文字を切り替える
4. 一本指は選択中ツールで編集し、二本指は移動と拡大縮小を行う
5. 2人または4人の出撃地点を地面へ吸着して配置する
6. テスト画面で対応済みの風ギミックを設定する
7. ゲーム同系統の背景・地形・キャラクター表示で、共有ゲーム物理による弾道・衝突・爆発地形破壊・足場喪失後の落下を確認する
8. 自動検証後、JSONまたはZIPを保存・共有する
9. 対象ゲームのカスタムステージ画面からインポートする

編集内容はIndexedDBへ自動保存します。IndexedDBが利用できない環境では、そのセッション内のメモリ保存へ切り替わるため、JSONまたはZIPを早めに保存してください。

端末のメモリまたはCPUコア数が少ない場合は、ホームの「軽量表示」を自動で有効にします。手動でも切り替えられ、有効時はCanvasのDPRを1へ抑え、編集グリッドと装飾描画を省略します。この設定は下書きと一緒に保存されます。非表示画面のCanvasは描画しません。

## ゲーム同系統のステージ表示

`地形`、`出撃`、`テスト`のCanvasは、対象ゲームと同じ4背景アセットとゲーム由来の空・地形配色を使います。地形には表面の縁、地層、石、ノイズを描き、対象ゲームの既存キャラクター画像を同じ寸法で表示します。

3画面の`横画面`ボタンはマップ画像の外にあります。Screen Orientation APIを利用できるAndroidのインストール済みPWA等では、全画面表示と横向き固定を試みます。自動回転に対応しないiPhone Safari等では、画面回転ロックを解除して端末を横へ向ける案内を操作欄に表示します。いずれも機能検出を行い、横向きでは地形ツール、出撃設定、テスト操作をマップ右側へまとめます。

地形画面はデザインアプリと同じく、マップを広く保つ構成です。常時並んでいた地形ツールは`選択中`ボタンへ集約し、押した時だけ一覧を表示して、選択後は自動で閉じます。`横画面 / 倍率 / 設定`もマップ外の操作帯へ移し、ステージ画像にはボタンを重ねません。ブラシサイズなどの細かな設定は初期状態で隠し、`設定`を押した時だけ前面のフロートパレットへ表示します。

キャラクター寸法ガイドはドラッグでき、当たり判定が地形へ重なる、または画面外へ出ると赤色で警告します。警告時は`赤いキャラを安全位置へ`で、現在位置に最も近い接地可能な足場へまとめて吸着できます。移動はUndo/Redoと自動保存の対象です。このガイドは編集補助専用で、正規のステージJSON、ZIP、ゲーム用データには含めません。

`文字`ツールでは、1〜8文字、書体、塗り／輪郭、大きさ、補強幅を選び、マップをタップして文字の形を地形へ追加できます。`ステージ中央へ置く`なら位置合わせなしで中央へ配置できます。文字は配置時に既存の地形グリッドへ変換されるため、ゲーム内で足場・衝突・砲撃・地形破壊の対象になります。保存ファイルへフォントや任意コードは含めず、端末間では変換済み地形を同じ内容として再現します。

`テスト`画面では、Canvas直下に左右移動、テスト砲撃、リセット、砲撃角度、威力をまとめた操作帯を置き、スマートフォン縦画面ではマップと一体で表示します。風の詳細設定は操作帯の下へ分離しているため、移動や砲撃の操作中もマップを確認できます。

## PWA

- iPhone: Safariの共有ボタンから「ホーム画面に追加」
- Android: Chromeのメニューから「アプリをインストール」または「ホーム画面に追加」
- 未インストールのSafari/Chromeでも同じ機能を利用可能
- 初回オンライン表示後はアプリシェルと共有モジュールをオフライン利用可能
- 更新は編集中の下書きを保存してから適用

## 共有モジュール

- `../../shared/stage-core.js`: スキーマ、決定的生成、正規化、検証、ハッシュ、物理、ゲーム変換
- `../../shared/stage-storage.js`: IndexedDB保存とスキーマ移行
- `../../shared/stage-zip.js`: ZIP作成、ZIP Slip・容量・形式検証を伴う読込

Stage Studio側で独自のゲーム物理を持たず、共有モジュールの弾道・衝突・地形処理を優先します。フォールバック物理は共有スクリプトの読込失敗を画面で知らせるための限定的な保護処理です。

## セキュリティ

- 宣言型JSONのみを扱い、任意JavaScript・HTML・CSS・外部URLを拒否
- 厳格なCSPで外部通信、外部画像、埋め込み、任意スクリプトを禁止
- JSON/ZIPの容量、ZIPパス、解凍後容量、件数、座標、有限数、許可リスト、ハッシュを検証
- 文字列はHTMLとして挿入せず、`textContent`で表示
- ファイル名は共有コアで安全化

## MVPの範囲

固定ステージサイズ、破壊可能な通常地形、既存4テーマ、最大4出撃地点、ステージ全体の風に対応します。多角形、範囲移動・コピー、上下反転、部分対称化、ワープ、回復地点、移動床、任意背景アップロード、オンライン投稿、QRコードは将来拡張です。

壊れない鋼鉄地形は`壊れない鋼鉄（準備中）`の無効な項目としてだけ表示します。ゲーム本体の素材処理が対応するまで、選択、下書き保存、JSON/ZIP出力、ゲームへのインポートはできません。
